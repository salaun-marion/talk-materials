Qu’est-ce que le JDH ?

Journal of Digital History (JDH)

Journal académique en ligne basé sur le principe de plusieurs niveau de lecture pour chaque article (narratif, herméneutique, code et données). Le journal est en accès libre et n’engendre aucun coût que ce soit pour les auteurs ou pour les lecteurs.

En association avec la maison d’édition De Gruyter Brill.

Lien : https://journalofdigitalhistory.org/

Cycle de vie d’un journal

  1. gérer les soumissions : accepter, décliner, …
  2. contacter les auteurs régulièrement
  3. réaliser des revues techniques de leur travail (débugger le code, vérifier que les packages soient bien installés …)
  4. organiser les peer reviews
  5. corriger les erreurs de frappes, orthographe
  6. vérifier la mise en page
  7. publier
  8. faire la promotion de l’article
  9. l’archiver avec le pdf

Un exemple de parcours du combattant

Pour obtenir un token qui a une durée illimitée avec Facebook, il vous faudra :

  1. Un long-lived user access token (dure 60 jours) avec la requête suivante
curl -i -X GET "https://graph.facebook.com/{graph-api-version}/oauth/access_token?       
  grant_type=fb_exchange_token&               
  client_id={app-id}&     
  client_secret={app-secret}&     
  fb_exchange_token={your-access-token}"
  1. Il faut récupérer l’app-id
  2. L’app-secret
  3. Puis générer l’access-token

  1. Une fois que l’on a eu tout ça, on doit récupérer un long-lived page access token
  2. Il faudra pour se faire… récupérer la graph-api version
  3. Puis le app-scoped-user-id
  4. Et réutiliser le long-lived user access token obtenu à l’étape 5 🤪

Et puis, il faut planifier donc gérer une heure de planification avec un scheduler.

Mais si c’est aussi complexe, pourquoi automatiser ?

… parce que automatiser amène aussi des avantages

  • risque d’oubli sur le “comment faire” par l’humain car on ne publie pas tous les jours
  • vérification systématique si tous les fichiers sont présents (tweet.md, socialmediacover.png)
  • permet d’investir la possibilité de répliquer sur d’autres réseaux sociaux (Linkedin, Mastodon, Threads…)
  • libère du temps pour d’autre tâche(s) : aider les auteurs par exemple

mais surtout…

Apprentissage de nouvel compétence (code, vision d’ensemble des étapes) que ce soit par l’équipe mais aussi par nos étudiants.

En programmation, on ne réinvente pas la roue à chaque fois.

… le développeur “aime” l’automatisation

  • les tests et déploiement en production sont souvent automatisés
  • identifier les éléments à automatiser
  • utiliser de la visualisation comme un dashboard pour mieux gérer son travail (« DORA Value stream mapping for software delivery » (s. d.))

“Computers perform repetitive tasks; people solve problems.” (Forsgren (2018))
